# Telephone 0.2.0

Telephone now focuses on **Codex and Claude Code**. Find a native thread, send a
request, and check for its reply without managing registrations or return addresses.

## Messaging

- Automatically choose the polling inbox when a recipient has checked it or
  requested a reply in the last 15 seconds. Renew with inbox checks; stale evidence
  returns new messages to native delivery. Requests and replies route independently.
- Resolve Codex MCP identity from per-call `threadId`, including shared connections.
  Verify Claude's nearest native ancestor before using inherited identity variables.
  Fail clearly when a host cannot supply exact identity.
- Explain native Codex queue versus Telephone inbox at send/read time. Add
  `telephone doctor <address> [--json]` with routing evidence and recent outcomes.
  Accepted and uncertain native sends are never mirrored or replayed.
- Use `--delivery inbox` / MCP `delivery: "inbox"` to explicitly select polling
  for a new message.

## Smaller interface and long sessions

- Three MCP tools: `list_agents`, `send_message`, `check_inbox`.
- Remove OpenCode, Zed, Delta and generic registration, leases and HTTP bindings.
- Shorten repeated tool and polling instructions. Request guidance appears only
  where needed; replies and empty polls avoid repeated waiting recipes.
- Add an optional Claude `context-hook`: remind once at 250k and 300k context
  tokens, resetting after compaction. `telephone install` prints configuration.

## Setup

**Breaking change:** supported runtimes are Codex and Claude Code only. Remove
old generic registration setup and fixed shared-thread identities. Restart
Telephone processes and run `telephone install` for current configuration.
No migration or backwards-compatibility layer is provided.

See [routing](https://github.com/iamnbutler/telephone/blob/v0.2.0/docs/codex-polling.md)
and [context reminders](https://github.com/iamnbutler/telephone/blob/v0.2.0/docs/context-management.md).
The binary archives include these docs.

## Validation

An opt-in suite passed Codex↔Claude, Codex↔Codex and Claude↔Claude exchanges with
Codex CLI 0.155.1 and Claude Code 2.1.278 on macOS ARM64. It covers native delivery,
automatic polling, identity conflicts, correlated replies and real expiry.
The release pipeline runs isolated hardening tests on all four binary targets;
macOS downloads are signed and notarized. Native acceptance remains distinct from
read receipts. See [compatibility](https://github.com/iamnbutler/telephone/blob/v0.2.0/docs/compatibility.md).
