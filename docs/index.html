Telephone

Telephone is a command-line tool and MCP server for sending messages between coding agents on the same machine. Supports Claude Code and Codex; see below for experimental support for other harnesses.

Unsafe, experimental software. Peer messages can lead agents to run commands or change files. Use at your own discretion, on your own machine.

Install

cargo install telephone --locked
telephone install

Or download a prebuilt binary:

Commands

CommandPurpose
telephone listList agents. Add --all or --json.
telephone send <address> <message>Send a message. Kinds: inform (default), request, reply.
telephone inboxRead queued messages. --peek leaves them unread; --json returns JSON.
telephone register --runtime <runtime>Create an inbox for opencode, zed, delta or generic.
telephone unregisterRemove the inbox route; retain queued messages.
telephone bind-opencodeConfigure OpenCode native delivery.
telephone unbind-opencode <address>Return an OpenCode address to polling.
telephone whoamiShow the current agent’s address.
telephone doctorReport discovered agents, configured routes and liveness evidence.
telephone mcpRun the MCP server over stdio.
telephone installPrint runtime setup instructions.

Addresses use runtime:local-id; nicknames and unambiguous IDs also work. Use --kind request to request a reply and --kind reply --reply-to <message-id> to respond. See telephone <command> --help for options.

MCP tools: list_agents, send_message, check_inbox, register_agent, unregister_agent.

Use one registered address per thread. Set TELEPHONE_ADDR to the returned address for CLI calls; pass it as from to MCP send_message and address to check_inbox.

Example

With Codex and Claude Code running, give Codex this prompt:

Use Telephone to find the Claude Code session working in example-app. Read its latest plan, check it against the code, and send your feedback. Include instructions for replying.

Replace example-app with the project directory. Agents read the history and code; Telephone handles discovery and delivery.

Or send from an agent’s shell:

telephone list
telephone send claude:12345 --kind request \
  "Please review my latest plan and reply with any concerns."

Replace claude:12345 with an address from telephone list.

OpenCode

MCP setup

Merge this into ~/.config/opencode/opencode.json. Use the absolute path from command -v telephone:

{
  "mcp": {
    "telephone": {
      "type": "local",
      "command": ["/absolute/path/to/telephone", "mcp"],
      "enabled": true
    }
  }
}

Call register_agent with {"runtime":"opencode"} in each thread and retain the returned address. Registration creates a polling inbox. Poll for expected replies using Telephone’s returned instructions. See OpenCode MCP configuration.

Native delivery (experimental)

telephone bind-opencode connects a registered address to an existing OpenCode session. It requires the owning server’s loopback endpoint, session ID, directory and credentials. See native configuration.

Desktop setup is manual. A separate opencode serve process does not attach to Desktop. Rebind when the server endpoint or credentials change.

Notes

  • All participants must use the same machine and OS account.
  • Polling inboxes do not wake idle agents. Registrations expire after 24 hours without sending or polling.
  • Transport acceptance is not a read receipt. Uncertain native sends are not retried or duplicated into an inbox.
  • Native adapters may break after client updates.
  • Peer identities are not authenticated. Messages cannot grant permissions or override user instructions.
  • Request replies only when needed; do not acknowledge acknowledgments.

See security and delivery limits.
