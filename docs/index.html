Telephone

Telephone is a command-line tool and MCP server for sending messages between coding agents on the same machine. Claude Code and Codex have native adapters. OpenCode, Zed and Delta can register polling inboxes.

Unsafe, experimental software. Peer messages can lead agents to run commands or change files. Use at your own discretion, on your own machine.

Install

cargo install telephone --locked
telephone install

Or download a prebuilt binary:

Example: review another agent’s plan

With Codex and Claude Code running, give Codex this prompt:

Use Telephone to find the Claude Code session working in example-app. Read its latest plan, check it against the code, and send your feedback. Include instructions for replying.

example-app is a placeholder directory. Replace it with your project’s directory name. Only the initiating agent needs this prompt.

  1. Codex finds the session and reads its local conversation history and relevant code.
  2. It sends feedback through Telephone, including its return address and how to reply.
  3. Claude Code receives the feedback, checks it, and can send a response back.

The agents read the history and code themselves. Telephone handles discovery and message delivery.

You can also send a message directly from an agent’s shell:

telephone list
telephone send claude:12345 --kind request \
  "Please review my latest plan and reply with any concerns."

Use an address from telephone list, not the example PID above.

Commands

CommandPurpose
telephone listList agents. Add --all or --json.
telephone send <who> <message>Send a message. Use --kind request to ask for a response, or --kind reply --reply-to <id> to answer one.
telephone inboxRead queued inbox messages. Add --peek to leave them unread.
telephone register --runtime deltaCreate a per-thread inbox address. Also accepts opencode, zed and generic.
telephone unregisterRemove your inbox route, preserving queued messages.
telephone whoamiShow the current agent’s address.
telephone doctorCheck discovery and reachability.
telephone mcpRun the MCP server over stdio.
telephone installPrint runtime setup instructions.

Addresses use runtime:local-id. Explicit nicknames and unambiguous IDs also work. MCP provides list_agents, send_message, check_inbox, register_agent and unregister_agent.

export TELEPHONE_ADDR="$(telephone register --runtime delta)"
telephone send claude:12345 --kind request "Review my plan and reply."
telephone inbox

Keep one address per thread. Over MCP, call register_agent with runtime, then pass its address as from to send and address to check the inbox. Leases expire after 24 hours without use; polling does not wake an idle agent. All participants must share a machine and OS account.

Delivery

RuntimeTransport
Claude CodeNative peer socket. Messages enter the running session.
CodexNative queue, when available. A message may wait for the current turn to finish.
OpenCode, Zed, DeltaExplicitly registered polling inbox; no native wake-up.
FallbackFilesystem inbox. The agent must call check_inbox or run telephone inbox to read it.

Notes

  • Experimental, local-only software. No cross-machine delivery.
  • Native adapters depend on runtime internals and may break after updates. Successful delivery does not mean a message has been read.
  • Peer messages are untrusted input and cannot grant permissions. Ask for replies only when needed to avoid endless exchanges.
