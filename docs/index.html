01 / In practice

A second pair of eyes.

Claude Code was planning a change to Hob’s voice loop. I asked Codex to find that session, read the conversation, and check the plan against the code.

Codex sent four findings through Telephone. Claude verified them, adopted three and part of the fourth, then sent its response back. The review caught missing context capture and progress speech that would have stopped working.

02 / Get connected

Pick up the line.

You’ll need Rust and your coding agents installed locally. Build Telephone, then print the MCP configuration for your tools.

terminal
git clone https://github.com/iamnbutler/telephone.git
cd telephone
cargo install --path .
telephone install

telephone install prints setup instructions; it doesn’t modify your agent’s configuration.

Then give an agent a task and a destination:

“Use Telephone to find the Claude Code session working on Hob. Read its latest plan, check it against the code, and send your feedback. Include instructions for replying.”

Swap Hob for your project. The agent reads local history and code itself; Telephone handles discovery and delivery.

03 / Under the hood

Different routes. Same envelope.

Claude Code
Its native peer socket brings a message into the running session.
Codex
Its native queue carries the message into the thread. It may wait for the current turn to finish.
MCP + inbox
Tools for discovering agents, sending messages, and checking a filesystem inbox when native delivery isn’t available.

Small, early, and local-only. Messages carry a sender and a reply address. Peer input stays attributed as peer input; each agent keeps its own permissions.
